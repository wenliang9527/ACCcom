## 1. TCP 端点栈专项(4510d1e..cff0a58 新增,本轮重点)

新增面:TcpSerialService.cs(630 行,ISerialService 的 TCP 传输实现)、EndpointSerialService.cs(106 行,按端口名分发)、TcpEndpoint.cs(79 行,端点解析)、SerialTools open_port TCP 参数、Program.cs finally Dispose、GUI 连接栏 tcp:// 全链路。

- **[P2] 握手可被并发 Send 抢先,「首包必为握手」不变量不成立**(TcpSerialService.cs:184 vs :196-201)。`_connValid = true` 在 :184 先置位,握手写 在 :197-201 才发生;两行之间 `TryPrepareSend`(:399)的 `_connValid` 检查已通过,并发 Send 线程可先抢到 `_sendGate` 先写——TCP 保序但锁不保握手优先,线上首包变成业务载荷:桥把载荷当行配置命令消费(或直接吞掉),窗口关闭,握手字节「19200E」作为垃圾直达目标设备,桥不换速。类注释(:20-23「so no caller send can precede it」)声称的不变量在该交错下不成立。触发场景:循环发送/触发器运行中用户重开 TCP 口。修复:把握手写挪到 `_connValid = true` 之前(连上即写,写完再宣告 IsOpen),窗口内 Send 按语义报「not open」;S 工作量。
- **[P2] GUI 多端口会话不支持 TCP 端点——与 MCP 侧能力不一致**(src/ACCcom/ViewModels/MainViewModel.cs:19 → src/ACCcom.Core/Services/MultiPortService.cs:37)。GUI 的 `_multiPort = new()` 走默认工厂 `() => new SerialService()`;MCP 侧已换 `EndpointSerialService`(Program.cs:45)。多端口面板输入 `tcp://host:port` 会落到 `SerialPort.Open` 直接失败,且错误语义是「串口不存在」而非「不支持 TCP」。GUI 单会话已换(MainWindow.xaml.cs:22)。修复:GUI 多端口工厂同样传 `() => new EndpointSerialService()`;S。
- **[P3] `_endpoint` 字段在生命周期锁外写入**(TcpSerialService.cs:142)。`TryParse(config.PortName, out _endpoint)` 在 `await _lifecycle.WaitAsync()` 之前;两个不同端点的并发 Open 可让先到者连到后到者的端点(返回值仍报成功)。窗口窄(需同会话并发不同端点 Open,MCP open_port 与 GUI 面板同时开是现实入口)。修复:解析结果作局部变量带入锁内;XS。
